## 2. 핵심 설계 — "잡 폴더" 규약

폴더 하나 = 상품 하나 = 영상 하나. 사람은 **입력 폴더에 던지고, 중간에 두 번만 확인**한다.

```
jobs/<상품명>/
├ 00-input/     ← 사람: ref-url.txt(참고영상 링크) | ref.mp4, capture/*.png(쿠팡 캡처), link.txt(인포크)
├ 10-script/    ← 자동: 원본대본.txt · 사투리대본.txt · 소싱키워드_중문.md   ⏸ 사람 확인 1
├ 20-voice/     ← 자동: narration.wav · subtitle.srt
├ 30-sources/   ← 사람: 소스 영상 파일 또는 urls.txt(붙여넣으면 자동 다운로드)  ⏸ 사람 개입 2
├ 40-out/       ← 자동: final.mp4
└ 50-upload/    ← 자동: 플랫폼별 제목·설명·해시태그 + 인포크 유도 댓글
```

## 3. 울트라플랜 (Phase 순서 = 착수 우선순위)

### Phase 1 — 참고 영상 → 대본 추출기 (3번) · 반나절
- URL 또는 파일 입력 → yt-dlp 다운로드(없으면 설치 안내) → 기존 Whisper STT → `원본대본.txt`
- yt-dlp 자동 감지 + 실패 시 "파일로 직접 넣기" 폴백 (틱톡은 자주 막힘)

### Phase 2 — 충청도 사투리 바이럴 대본 (4번) · 2시간
- `script-prompts.mjs`에 톤 프리셋 추가: **충청도 사투리 · 구매욕구 폭발**
  - 규칙: 15~25초 = 45~70자, 첫 1.5초 후킹, "~여", "~겨", "~하잖유" 어미, 과장 금지·체감 강조
- 원본대본 → 사투리 대본 변환 (기존 신속정확 2초안+심사 엔진 재사용)

### Phase 3 — 소싱 팩 생성 (6번) · 2시간
- 대본 → 문장별 **중국어 검색어 3개 + 필요한 장면 설명** → `소싱키워드_중문.md`
- 샤오홍슈/틱톡에 그대로 복붙 가능한 형태 (문장번호 매핑 포함)

### Phase 4 — 소스 수집 (7번) · 1일 ★최대 병목
3안 중 **A+C 하이브리드** 추천:
- **A. URL 일괄 다운로드**: `30-sources/urls.txt`에 링크 붙여넣기 → yt-dlp 일괄 받기 + 9:16 정규화. 현실적·안정적
- **B. 브라우저 자동 검색·수집**: 샤오홍슈/틱톡 봇 차단이 강해 취약 → **비추천** (드롭샷 자동화에서 이미 겪음)
- **C. AI 생성으로 대체**: 쿠팡 상품 이미지 → 힉스필드/시댄스 i2v (이미 구현됨). **저작권 리스크 0**
- 부족한 장면은 C로 메우는 구조 → 사람 노가다 최소화

### Phase 5 — 업로드 패키지 (11번) · 3시간
- 완성 후 틱톡/인스타/유튜브/네이버클립/X 각각의 후킹 제목·설명·해시태그 + 인포크 유도 댓글 → `50-upload/upload.md`

### Phase 6 — 원클릭 체인 (비서 모델) · 1일
- "잡 폴더 열기" 한 번 → 규약대로 자동 진행, 사람 개입 지점(⏸)에서 멈추고 알림
- 기존 작업 큐에 얹어 **여러 상품 동시 진행** (실행은 순차, 접수 무제한)

### 레시피 영상
같은 파이프라인에 **프롬프트 프로필만 교체**(재료→단계→팁 구조, 톤 변경). Phase 2에서 프로필 구조를 만들어두면 프리셋 추가만으로 끝.

## 4. 리스크 (솔직하게)

1. **저작권** — 남의 틱톡/샤오홍슈 영상을 수익화 영상에 쓰는 건 클레임·계정 정지 리스크가 실재한다(업계에 흔한 방식이지만 리스크가 없어지진 않음). Phase 4의 **C안(상품 이미지 AI 영상화) 비중을 올릴수록 안전**하고, 판매자 제공 소재·직접 촬영이 가장 안전.
2. **yt-dlp 안정성** — 틱톡/샤오홍슈는 자주 막힌다. 100% 자동은 보장 못 하며 파일 직접 넣기 폴백이 필요.
3. **시간 절감 기대치** — 30~60분 → **8~15분**. 소스 수집이 여전히 병목(그래서 Phase 4가 핵심).
