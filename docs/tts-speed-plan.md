# 낭독(TTS) 속도 개선 플랜

> 2026-07-06 작성. 당분간 1인 사용 전제 — 구현은 보류하고 플랜만 확정.
> 현재 상태: 로컬 Qwen3-TTS(RTX 4060 8GB) 기준 5분 대본 ≈ 6~12분 생성.
> 목표: 내 목소리 클로닝을 유지하면서 체감 대기를 30초 수준으로.

## 현재 병목 정리

| 병목 | 원인 | 영향 |
|---|---|---|
| 생성 속도 자체 | 1.7B 자기회귀 모델 + 노트북 GPU | 오디오 길이의 1~2배 소요 |
| 전량 재생성 | 대본 일부만 고쳐도 전체 덩어리 재생성 | 반복 수정 시 매번 수 분 |
| 전부 끝나야 재생 | 최종 wav 완성까지 대기 | 체감 대기 = 전체 생성 시간 |
| 연출 분석 대기 | AI 낭독 연출 추론(에이전트/API) | 시작 전 수십 초 추가 |

## 단계별 플랜 (우선순위 순)

### 1단계 — 스트리밍 미리듣기 (체감 개선 최대, 0원)
첫 덩어리가 완성되는 대로 모달에서 바로 재생 시작. 이후 덩어리는 백그라운드에서 이어 붙임.
- 낭독 엔진은 이미 덩어리 단위로 생성하고 진행 파일(`.progress.json`)도 기록 중 → 완성된 part wav를 서버가 순서대로 서빙하는 API + 모달에서 연속 재생만 추가하면 됨
- 예상 작업량: 반나절
- 효과: 체감 대기 6~12분 → **약 30초** (첫 덩어리 생성 시간)

### 2단계 — 덩어리 캐시 ✅ 구현 완료 (2026-07-06)
덩어리 텍스트+목소리 서명(파일 크기·수정시각·전사)의 해시를 키로 wav 캐시. `tmp/tts-cache/`, 600개 상한 초과 시 오래된 것부터 삭제.
- 실측: 2덩어리 낭독 45.6초 → 재실행 0.9초 (전량 캐시)
- 함께 들어간 안정화: 동시 낭독 차단(GPU 1개 직렬), 덩어리 타임아웃 4→10분 + 1회 재시도
- 효과: 도중 실패해도 재시도하면 없는 덩어리만 재생성 — 2시간짜리 사고가 몇 분 복구로 바뀜

### 3단계 — ElevenLabs 유료 프로바이더 (급할 때 돈으로 시간 사기)
낭독 생성 시 "무료(내 GPU) / 빠름(ElevenLabs)" 선택. 키는 환경설정에 저장.
- 사전 준비(사용자): elevenlabs.io 가입 → 내 목소리 샘플 업로드해 클로닝 보이스 생성 → API 키 발급
- 구현: `src/tts/elevenLabsProvider.ts` (TtsProvider 인터페이스 그대로), 환경설정에 키 입력칸, 낭독 UI에 프로바이더 선택
- 예상 작업량: 한나절
- 효과: 5분 대본 ≈ **30초**. 비용: 월 $5~22 구독(분량 한도 있음)
- 유보 사유: 1인 사용 + 0원 원칙이라 1·2단계로 충분할 가능성이 높음. 1·2단계 써보고 결정.

### 4단계 — 로컬 추론 최적화 (여유 있을 때)
- flash-attention / torch.compile 적용 시도 (예상 10~30% 개선)
- 대본 확인용 "빠른 초안 모드": 연출 추론 생략 + 덩어리를 크게(240자) 잘라 오버헤드 축소
- GPU 업그레이드 시 자동 수혜 (데스크톱 4090이면 3~5배)

## 결정 기록
- 브루/캡컷이 빠른 이유 = 데이터센터 GPU + 기본 보이스(클로닝 아님) + 스트리밍 재생 트릭. 같은 트릭(1단계)은 우리도 0원으로 가능.
- CPU는 이 작업과 무관 — GPU가 전부.
- OpenAI TTS는 내 목소리 클로닝이 안 돼서 제외. 국내(수퍼톤/타입캐스트)는 개인 클로닝 제약으로 제외.
