# 롱폼 자막 탭 — 설계

> 2026-08-29 작성. 출처: 사용자가 준 노션 "자막 자동화 실습 자료"(Whisper + 클로드코드 워크플로우).
> 승인된 결정: 파일 직접 선택 / 대본은 붙여넣기·파일 둘 다 / 엔진은 기본값+선택 가능 / 결과는 원본 옆에 저장 / WhisperX 설치함.

## 1. 무엇을 만드나

영상이나 음성 파일 하나를 넣으면 **롱폼용 SRT 두 개**가 나온다. 수동편집 탭에 흩어져 있던 자막 기능을 "넣고 → 기다리고 → 받는" 한 줄 흐름으로 묶는 전용 탭.

```
영상/음성 파일 ─┬─→ ① 세밀 STT ─→ ② 대본 대조 보정 ─→ ③ 롱폼 재편성 ─→ ④ 공백 메움 ─→ ⑤ 검수
   (대본: 선택) ┘                   (대본 없으면 건너뜀)
출력: <원본이름>_정렬.srt  +  <원본이름>_정렬_공백메움.srt  +  검수 리포트(화면)
```

## 3. 계약

### CLI
```
shorts-factory longform-captions <media> [--script <file>] [--engine <method>] [--align] [--json]
```
- 무거운 일(STT·정렬)은 CLI에서. 서버는 잡 큐에 얹고 진행률만 중계한다(아키텍처 원칙 2).
- 출력은 원본 파일 옆: `<이름>_정렬.srt`, `<이름>_정렬_공백메움.srt`. **기존 파일을 덮어쓰지 않는다**(노션 규칙).

### 서버
```
POST /api/longform-captions   { mediaPath, script?, scriptPath?, engine?, align? } → { jobId }
GET  /api/jobs/:id                                        (기존 잡 큐 재사용)
```

### ② 보정 규칙 (노션 원문 그대로)
- 대본은 **참고용**. 강제로 1:1 일치시키지 않는다 — 실제 음성이 우선.
- 고칠 것: 오타, 영어, 숫자, 고유명사.
- **타임스탬프는 절대 건드리지 않는다.** 텍스트만 교체한다.
- 큐 개수가 달라지면 보정 결과를 버리고 원본을 쓴다(안전장치).

### ⑤ 검수 항목
1. cue 번호 순서 · 2. 한 cue = 한 줄 · 3. 줄바꿈 없음 · 4. 겹침 없음
5. 공백메움본에 공백 없음 · 6. 너무 짧거나 긴 자막 없음(18~44자 기준) · 7. 빈 자막 없음

## 5. 결정

| 결정 | 이유 |
|---|---|
| WhisperX를 `.venv-stt`에 격리 설치 | TTS venv(`.venv-tts`)의 torch를 건드리면 낭독이 깨진다. 디스크보다 낭독이 중요 |
| 보정은 텍스트만 교체, 큐 수가 바뀌면 폐기 | AI가 타임스탬프를 재생성하면 싱크가 통째로 밀린다(노션이 가장 강조하는 금지사항) |
| 결과를 원본 옆에 저장 | 노션 규칙. 프로젝트에 묶이지 않은 "컷편집 끝난 영상"이 입력이라 프로젝트 폴더는 맞지 않다 |
| 대본 없이도 동작 | ②만 건너뛰면 나머지 셋은 그대로 유효하다 |

## 6. 완료 기록 (2026-08-29)

실측 결과 — 16분 낭독 파일(972초):
- WhisperX 단어 큐 **1723개** → 롱폼 자막 **205줄**
- 글자수 최소 10 / 평균 33 / 최대 44 — 노션 기준(18~44) 안에 들어옴
- 검수: 길이 경고 1건(마지막 짧은 줄) 외 문제 없음. 공백메움본은 빈 구간 0

30초 샘플로 서버 경로 전체 확인:
- 단어 65개 → 자막 7줄, 대본 보정 2배치 전부 성공, SRT 2개 생성, 검수 모두 통과
- 걸린 시간 **약 5분** — 대부분이 모델 로딩(large-v3 + 정렬 모델)과 CPU 정렬이다. 길이에 비례하지 않는 고정비가 크다.

### 실행에서만 드러난 버그 두 개 (단위 테스트로는 안 잡힘)
1. **cuDNN을 못 찾아 즉사** — ctranslate2가 venv 안 torch의 cuDNN DLL을 보지 못한다. `torch/lib`을 PATH 앞에 붙여 해결.
2. **전사·정렬 GPU 충돌로 즉사** — whisperx CLI는 한 프로세스에서 ctranslate2(전사)와 torch(정렬)를 함께 GPU에 올린다. 전용 실행기(`scripts/whisperx_stt.py`)로 **전사는 GPU → 모델 해제 → 정렬은 CPU** 순서로 분리해 해결.

### 남은 것
- 비서 도구로 노출(계획 6단계)은 하지 않았다. 임의 경로를 다루는 기능이라 에이전트에 열기 전에 경로 제한을 다시 설계해야 한다.
- 진행률 표시가 없다(요청 하나가 몇 분 걸린다). 잡 큐에 얹는 편이 낫다.

## 7. 속도·정확도 개선 (2026-08-29 저녁)

측정부터 했다(30초 오디오):
```
[개선 전] import 8.7s · 모델로딩 89.8s · 전사 22.5s · 정렬모델 4.3s · CPU정렬 37.5s = 173초
[개선 후] ─────────────────────────────────────────────────────── 27초
```

- **정렬을 GPU로 되돌렸다** — 전사(ctranslate2)와 정렬(torch)을 각각 별도 프로세스로 실행하니 충돌 없이 둘 다 GPU를 쓴다. 정렬만 보면 5.0초 → 0.7초.
- **대본을 STT 힌트로 주입** — `initial_prompt`에 대본 앞부분(400자)을 넣어 고유명사·숫자·영어를 처음부터 맞게 받아쓴다. 사후 보정은 그대로 유지해 2중으로 거른다.
- batch_size 8 → 16, 모델 선택(large-v3 / turbo) 추가.

**16분 오디오 실측: 3분 19초** (단어 큐 1723개, 품질 동일). 대략 영상 길이의 1/5.

UI도 다시 만들었다: 드래그&드롭 존, 4단계 진행 표시, 예상·실제 소요 시간, 세부 설정 접기.

### 아직 남은 것
- 모델 로딩(콜드 스타트 90초)은 그대로다. TTS 데몬처럼 상주시키면 없앨 수 있다.
- 서버가 단계별 진행률을 보내지 않는다(UI가 시간으로 추정). SSE나 잡 큐로 바꾸면 정확해진다.
